# Faint 코드 구조와 변경 원칙

이번 구조 정리는 화면·단축키·입출력 형식·편집 동작을 유지하는 리팩터링입니다. 새로운 기능을 추가하거나 기존 동작을 고치는 작업과 분리해서 검토합니다.

## 모듈 책임

| 파일 | 책임 |
| --- | --- |
| `faint/app.py` | KDE 초기화, QApplication 생성, 실행 및 화면 진단. 기존 `faint.app`의 주요 클래스·함수 import도 유지합니다. |
| `faint/document.py` | 레이어 이미지, 합성, 캔버스 크기, 붙여넣기, 문서 스냅샷. UI와 파일 대화상자에 의존하지 않습니다. |
| `faint/imaging.py` | 투명 이미지 생성과 연결 영역 채우기. |
| `faint/canvas.py` | 캔버스 렌더링, 좌표 변환, 마우스 제스처, 선택 이미지와 그 아래 배경 관리. |
| `faint/window.py` | 사용자 명령, 실행 취소, 레이어·선택·팔레트 상태 및 UI 갱신 조정. |
| `faint/ui.py` | 위젯 배치, 메뉴와 도구 모음 생성, 신호 연결. 생성 순서·크기·문구를 유지합니다. |
| `faint/tools.py` | 도구 순서, 이름, 단축키, 상태바 설명, 도구별 기본 굵기. |
| `faint/storage.py` | `.faint`, PNG, JPEG 로딩과 원자적 저장. 실패를 예외로 전달하고, 창이 사용자 메시지를 표시합니다. |
| `faint/dialogs.py` | 캔버스 크기 입력과 비율 잠금. |
| `faint/widgets/palette.py` | 현재 색과 팔레트 색상 칸 렌더링. |
| `faint/widgets/layers.py` | 레이어 미리보기, 눈·삭제 버튼, 드래그 순서 변경, 고정 도크. |
| `faint/qt_compat.py` | 컴파일된 함수와 배포판 Shiboken의 호환성 처리. 일반 Python 실행에는 적용하지 않습니다. |

의존 방향은 `app → window → UI/Canvas/Document/Storage`입니다. UI는 창에 있는 명령을 연결하지만 창 클래스를 import하지 않습니다. 문서와 저장 모듈에서 창을 참조하지 않습니다.

## 유지해야 하는 상태 규칙

### 문서와 실행 취소

- `Document.layers`는 아래에서 위 순서입니다. 화면 목록은 역순입니다.
- 고정 배경은 그림 레이어와 별도인 `background_white` 값으로 관리합니다.
- 그림 레이어가 없으면 `active == -1`이며, 그 외에는 유효한 레이어 인덱스입니다.
- `snapshot()`은 QImage를 복사합니다. 이후 그리기가 과거 실행 취소 상태를 수정하면 안 됩니다.
- 편집 명령은 변경 전에 `Window.checkpoint()`를 한 번 호출합니다. 새 편집이 생기면 다시 실행 기록을 비웁니다.

### 캔버스와 선택

- 문서 좌표는 이미지 픽셀입니다. `offset`과 `zoom`은 화면 표시 위치와 배율이며 저장 이미지 크기를 바꾸지 않습니다.
- `Canvas.margin`은 기존 핸들 좌표 계산에서 쓰이는 논리적 오프셋입니다. 화면 좌표와 문서 좌표를 혼용하지 않습니다.
- `selection_pixels`는 처음 선택한 원본, `selection_base`는 원래 선택 영역을 비운 레이어입니다. 매 이동마다 원본을 다시 캡처하지 않습니다.
- 이동·크기 조절마다 `selection_base`와 원본으로 결과를 다시 합성합니다. 목적지의 배경이 다음 이동에 섞이면 안 됩니다.
- 캔버스 밖으로 이동한 선택 원본도 선택이 유지되는 동안 보관합니다. 선택 해제 시 현재 캔버스 안에 보이는 결과가 확정됩니다.
- 브러시·지우개의 안티앨리어싱과 픽셀 도구의 정수 좌표 경로는 서로 다릅니다.

### Qt UI와 빌드

- `refresh()`가 레이어 목록을 재구성할 때 신호를 막습니다. 프로그램이 행을 선택하는 동작을 사용자 편집으로 처리하면 안 됩니다.
- 레이어 드래그는 자체 QDrag 생명주기를 사용합니다. 기본 Qt 드래그가 드롭 후 원본 행을 다시 지우지 않게 합니다.
- 현재 굵기 등 입력 위젯에 포커스가 있어도 그림의 복사·붙여넣기·실행 취소 단축키가 유지되어야 합니다.
- Qt 스타일, 팔레트, 폰트, 위젯 크기, 생성 순서는 화면 비교 대상입니다. 스타일시트나 전역 테마 설정을 기능 리팩터링에 섞지 않습니다.
- KDE 배포용은 시스템 PySide6·Qt·스타일 플러그인을 함께 사용합니다. `tools/`의 빌드 구성은 Python 모듈 분리 후에도 필요합니다.
- 공개 실행 경로는 `python -m faint`, `run.sh`, `run_faint.py`, `build.sh`입니다.

## 파일 호환성

`.faint`는 ZIP 안의 `document.json`과 `0.png`, `1.png` 등의 레이어 이미지로 구성됩니다. JSON 키와 레이어 순서, 이름, 표시 상태, 활성 인덱스, 배경 플래그는 기존과 동일합니다. 이름을 UI에서 표시하지 않더라도 저장 필드를 삭제하지 않습니다.

PNG는 보이는 레이어 합성과 투명도를 저장하고, JPEG는 흰 배경에 합성한 결과를 품질 95로 저장합니다. 저장할 때 목적지 옆의 임시 파일을 완성한 후 교체하므로 실패한 저장이 기존 파일을 덮어쓰면 안 됩니다.

## 검증

```bash
python -m unittest discover -s tests -v
ruff check faint run_faint.py
ruff format --check faint run_faint.py
```

화면·동작을 바꾸지 않는 큰 변경 전에는 기존 `faint/app.py`를 저장소 밖에 보관할 수 있습니다. 이 리팩터링의 이전 단일 파일 구현과 비교하는 도구도 포함합니다.

```bash
python tools/verify_refactor.py /path/to/pre-refactor/app.py
```

이 비교는 같은 머신·Qt 테마에서 실행합니다. 핵심 클래스의 AST, 도구별·선택 편집·확대·숨김 화면 16장, 클립보드 이미지, `.faint` 내부 데이터와 PNG/JPEG 파일을 비교합니다. Qt의 일시적인 포커스 애니메이션이 끝난 후 안정된 화면을 비교합니다. 이 도구는 클립보드 전달 데이터를 메모리 모형으로 수집하므로 데스크톱 클립보드를 바꾸지 않습니다. 실제 Qt 클립보드의 PNG 형식 제공은 별도의 자동 테스트로 검증합니다. 이전 구현은 유지보수 대상 코드로 저장소에 복제하지 않습니다.

빌드 검증도 별도로 필요합니다. Nuitka의 컴파일 함수와 Qt 신호 연결은 Python 직접 실행 테스트만으로 검증되지 않습니다.

```bash
./build.sh
./dist/run_faint.dist/faint --check-theme
```

## 이번 구조 변경의 검증 기록

- 기존 자동 테스트 27개를 유지하고 저장 계약 테스트 3개를 추가하여 총 30개 통과.
- 이동한 핵심 함수·클래스 13개의 AST가 주석·포맷·지역 변수 이름 정리를 제외하고 동일함을 확인.
- 같은 KDE/Darkly 환경에서 16개 장면을 변경 전 구현과 픽셀 단위로 비교하여 일치 확인.
- 선택 영역 복사 이미지, `.faint` ZIP 내부 데이터, PNG/JPEG 저장 바이트 일치 확인.
- 폴더 및 단일 파일 실행 파일을 실제 빌드하고, 초기 화면이 변경 전 Python 실행 화면과 픽셀 단위로 일치함을 확인.
- Ruff 정적 검사·포맷 검사 통과.

이 기록은 해당 환경에서 검증한 범위를 나타냅니다. 이후 기능 수정 시에도 기존 테스트와 빌드 실행 검증을 유지합니다.

## 현지화

`faint/i18n.py`는 영어·한국어 카탈로그, 언어 설정, Qt 기본 대화상자 번역을 관리합니다. `COMMON.SAVE`, `TOOLBAR.BRUSH`, `DIALOG.SAVE_ASK_DESCRIPTION`처럼 점으로 구분한 대문자 키를 사용합니다. `MESSAGES`의 각 키에는 `en`, `ko` 표시 문자열을 함께 정의하며, `tr(key, **values)`로 조회합니다. 키가 없으면 `KeyError`로 누락을 드러냅니다. 위젯의 키는 Qt 속성에 보관해 언어를 반복 전환해도 잃지 않습니다. 단축키는 번역 키와 분리해 유지하며 Qt 소유의 기본 버튼 번역만 Qt 원문 키를 따릅니다. `Window.retranslate()`는 표시만 갱신하며 문서, 선택 버퍼, 레이어 선택, 실행 취소를 재생성하지 않습니다.

언어 선택 순서는 세션용 `FAINT_LANGUAGE=en|ko`, 저장된 `QSettings("Faint", "Faint")`의 `ui/language`, 운영체제 언어 순서입니다. 한국어가 아닌 미지원 운영체제 언어에는 영어를 사용합니다. 파일명과 저장된 레이어 이름은 사용자 데이터이므로 번역하지 않습니다. Qt 기본 대화상자의 한국어 카탈로그는 빌드에 포함합니다. 운영체제 자체에서 제공하는 네이티브 대화상자의 일부 문구는 데스크톱 언어 설정을 따를 수 있습니다.


### 이미지 코덱과 데스크톱 연결

`storage.RASTER_FORMATS`는 저장 인코더와 레이어 드롭 확장자의 기준입니다. PNG·WebP는 알파를 유지하고 JPEG·BMP는 흰 배경에 합칩니다. GIF는 Qt가 첫 프레임을 읽고 Pillow가 정지 GIF를 저장합니다. 255색으로 양자화하고 255번 인덱스를 투명색으로 예약하며 알파 128 미만을 투명하게 처리합니다.

`assets/faint-mime.xml`은 ZIP 기반 프로젝트를 `application/x-faint`로 식별합니다. `tools/install_desktop.py`가 MIME 데이터베이스와 데스크톱 항목을 설치하고, `tools/project_mime.py`가 이 형식의 사용자 기본 앱만 Faint로 지정합니다. 삭제 시 같은 도구가 Faint 참조만 제거해 다른 파일 형식의 기본 앱과 사용자 주석을 유지합니다.
